# Banyan — Claude Code rules

## Stack
- Swift, iOS 17+, SwiftUI, SwiftData
- Architecture: MVVM
- Testing: Swift Testing (`import Testing`) — not XCTest
- No third-party dependencies for UI or business logic. Infrastructure SDKs are permitted where they replace significant boilerplate: supabase-swift is approved for Supabase auth, database, and storage access.

## Build and test commands
```
xcodebuild -scheme Banyan -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17' build
xcodebuild test -scheme Banyan -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17'
```

## Project generation
`Banyan.xcodeproj` is generated by XcodeGen from `project.yml` — it is not checked in.
After adding, moving, or deleting a source file, run `xcodegen generate`.
To change targets, build settings, or the deployment target, edit `project.yml` — never the `.pbxproj`.

## Hard rules — never break these

### Code quality
- No force unwraps in production code. Use `guard`, `if let`, `??`. Force unwraps allowed only in test code.
- No singletons. All dependencies injected via `init`.
- No business logic in Views. Views call ViewModels. Graph logic lives in GraphService only.
- No SwiftUI or SwiftData imports in `GraphService` or `Models/`.
- `@MainActor` on all ViewModels — mark the entire class, not individual methods.
- Default access to `private`. Use `private(set)` for read-only exposed state.
- `final class` on all SwiftData models and all ViewModels.
- Enum defaults set in `init()`, not at property declaration (SwiftData compiler bug).
- `throws` on any function writing to ModelContext.
- `///` doc comment on every protocol method and every ViewModel method.

### SwiftData relationships
- Only one side of a relationship declares `inverse:`. Never declare it on both ends.
- Back-references (`PersonUnionLink.person`, `.union`) must be optional. Non-optional back-refs crash on cascade delete.
- Default delete rule is `.nullify` — always state `.cascade` explicitly where needed.
- Insert object into context before building any relationships.
- In tests: `context.autosaveEnabled = false`, delete children manually before saving, build `ModelContainer` inline in each test function (not in suite `init()`).

### Deprecated SwiftUI APIs — never use
| Do NOT write | Write this instead |
|---|---|
| `.foregroundColor()` | `.foregroundStyle()` |
| `.cornerRadius()` | `.clipShape(.rect(cornerRadius:))` |
| `NavigationView` | `NavigationStack` |
| `onChange { value in }` | `onChange(of:) { old, new in }` |
| `Task {}` in `onAppear` | `.task {}` modifier |
| `onTapGesture` on a control | `Button` with accessible label |
| `AnyView` | `@ViewBuilder` or `Group` |
| `@StateObject` / `@ObservedObject` | `@State` / plain `let` with `@Observable` |
| `@EnvironmentObject` | `@Environment(Type.self)` |

### Never edit `.pbxproj` directly.

## Testing conventions
- Framework: `import Testing` — use `@Test`, `#expect`, `#require`
- `#expect` continues on failure; `#require` halts — use `#require` for preconditions
- Mark `@MainActor` on any suite that tests a `@MainActor` type
- Given-When-Then / Arrange-Act-Assert structure in every test

## UI conventions
- Never hard-code font sizes — use `.font(.title)`, `.font(.body)` etc.
- Minimum tap target: `.frame(minWidth: 44, minHeight: 44)` on all interactive elements
- Prefer small composable View structs over large bodies
- Every interactive element is a `Button` — never a bare `onTapGesture`

## @Observable property wrapper guide
| Situation | Use |
|---|---|
| View owns the object | `@State var vm = MyViewModel()` |
| View receives it, read-only | plain `let vm: MyViewModel` |
| View needs `$binding` on it | `@Bindable var vm: MyViewModel` |
| Flows across many view branches | `@Environment(MyViewModel.self)` |
