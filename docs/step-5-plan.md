## Cleanup discipline (this bit us before)

`simctl uninstall` does **not** reliably clear the app's sandbox preferences plist or SwiftData
store — during step 4 a seeded "Aryan Das" owner survived an uninstall and reappeared on the next
launch. The app's real `@AppStorage` lives in the **app container**, not the simulator's global
defaults domain, so `simctl spawn … defaults read` can show "domain does not exist" while the app
still has an owner. To truly reset:

```
xcrun simctl terminate "iPhone 17" com.aryandas.Banyan
xcrun simctl uninstall "iPhone 17" com.aryandas.Banyan
xcrun simctl get_app_container "iPhone 17" com.aryandas.Banyan data   # must error "No such file"
```
If the container still exists, delete it explicitly. Verify a clean state shows the **Welcome /
"Get started"** onboarding screen, not a populated tree, before you finish.

### Gaps already fixed in the spec vs. the earlier draft (context for reviewers)

The step-5 prompt was corrected before this handoff. What changed and why:

1. **Test count** — the draft said "44 tests passing"; the real baseline is **46**. Fixed to 46,
   and the done bar is 58 (46 + 12 new).
2. **Shared `graphService`** — the draft told `TreeTabView` to pass `GraphService()` into the
   sheet. That contradicts the step-4 PR-review decision to use one shared instance. The spec now
   passes the existing `self.graphService`.
3. **Sex was uneditable** — `PersonEditViewModel` carries `sex` and `save` writes it, but the draft
   `PersonEditView` had no Sex control, so the field was dead. Added a **Sex `Picker`** section.
   (This also closes the step-4 follow-up that the add flow never collected sex.)
4. **Delete safety** — the draft did inline `modelContext.delete(person)` with no guards. Two real
   breakages: **deleting the owner** leaves `ContentView` gated on a dangling `ownerPersonId` with
   no way to re-onboard; **deleting the focal person** leaves the tree on "No tree yet". The spec
   now: routes delete through `TreeMutationService.deletePerson` (unit-testable, prunes unions left
   with no partners), **hides Delete for the owner** (`canDelete: person.id != ownerPersonId`), and
   **falls back to the owner** in `refreshSnapshot()` when the focal person is gone.
5. **Sheet stacking** — presenting the add-person sheet in the same tick that dismisses the person
   sheet drops the presentation. The spec calls for deferring "Add …" until the person sheet is
   gone (`onDismiss` / a `pendingAddContext` stash). **This is the most likely runtime bug — verify
   it live.**

### Still-open judgement calls for the implementer

- **Photo support (`PhotosUI` + `PhotoStorageService`) is the heaviest, most optional piece.** If
  the session is running long or the picker fights the sheet's NavigationStack, it's the cleanest
  thing to split into its own step — the rest of the sheet (view/edit/delete/navigate) stands
  alone. Flag it rather than shipping it half-working.
- **Relationship labels** are plain ("Parent"/"Child"). Gender-aware labels from `person.sex` are
  explicitly deferred.
- **Deleting a partner from a 2-partner union** leaves the union (correct). Deleting the **sole**
  parent prunes the union, orphaning the children as roots (correct — they now have no known
  parents). There's a test for each; confirm the graph reads sensibly afterward.
