## Tooling — read before building

- **The Xcode project is generated by XcodeGen from `project.yml` and is gitignored.**
  After adding, renaming, or deleting ANY source file you must run `xcodegen generate`
  or Xcode won't see the file. This bites every new-file step.
- **Simulator is `iPhone 17`** (Xcode 26.6; there is no iPhone 16 on this machine).
- Build / test:
  ```
  xcodegen generate
  xcodebuild -scheme Banyan -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17' build
  xcodebuild test  -scheme Banyan -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17'
  ```
- CoreData "Failed to stat path … default.store" lines in test logs are benign host-app
  noise — tests use in-memory containers. Ignore them.

## What steps 1 & 2 already built (do not modify)

**Models (`Banyan/Models/`)** — pure of SwiftUI; `@Model` classes import SwiftData only:
- `Person` — `id, treeId, firstName, lastName, sex: Sex, birthDate/deathDate: PartialDate?,
  birthPlace/deathPlace, isPlaceholder, profilePhotoFilename, bio, createdAt`,
  `@Relationship(.cascade, inverse: \PersonUnionLink.person) links`.
  Computed: `fullName`, `initials`, `isDeceased`.
- `Union` — `id, treeId, type: UnionType, startDate/endDate, endReason`, cascade `links`.
- `PersonUnionLink` — `id, role: LinkRole (.partner/.child), childType: ChildType?`,
  plain optional `person`/`union` back-refs (no `@Relationship` — inverse lives on the parents).
- `PartialDate` — Codable struct, `year/month/day/isEstimated`, `.displayString`.
- Enums (`Sex`, `UnionType`, `EndReason`, `LinkRole`, `ChildType`): String, Codable, CaseIterable.
- `BanyanSchemaV1: VersionedSchema` wraps the three `@Model`s.

**`GraphService` / `GraphServiceProtocol` (`Banyan/Services/`)** — pure, no SwiftUI/SwiftData.
Step 3's ViewModel depends on exactly these:
- `parents(of:)`, `allPartners(of:)`, `children(of:)`, `siblings(of:)` (siblings = share a
  parent *union*; half-siblings from a different union are excluded), `unions(for:)`,
  `partners(of:in:)`, `allPeople(treeId:from:)`.

**`TreeViewModel` (`Banyan/ViewModels/`)** — `@MainActor @Observable`. Step 3 drives navigation
through it:
- `focusedPersonId: UUID?`, `navigationStack: [UUID]`
- `focus(on:)` (pushes previous focus; no-op if re-focusing current),
  `goBack()` (no-op on empty stack), `resetToRoot(ownerId:)`.

**Onboarding + shell (step 2)** — `ContentView` gates on `@AppStorage("ownerPersonId")`;
`MainTabView` (Tree/People/Settings tabs); `WelcomeView` + `NameEntryView` + `OnboardingViewModel`
create the owner `Person` and write `ownerPersonId` / `treeId` to `@AppStorage`.
`TreeTabView` is currently a **placeholder** — step 3 replaces it.

**SwiftData rules that must hold (why they exist):** single-sided `inverse:`; optional
back-refs (non-optional crashes on cascade delete); enum defaults in `init()` not at the
property (SwiftData compiler bug); in tests use `TestTreeBuilder` (in-memory container built
inline per test, `autosaveEnabled = false`).

## Step 3 scope (see spec for full detail)

The **3-generation focused tree view** — the app's primary screen. Always 3 rows centred on a
focal person: parents (top), focal + partner(s) + siblings (middle), children (bottom). Tap any
node to re-center. Empty slots are faint tappable placeholders that just `print(...)` for now
(real add-person flow is step 5). Connectors drawn with a `Canvas` fed by `anchorPreference`.

New files: `ThreeGenViewModel`, `ThreeGenView`, `PersonNodeView`, `PlaceholderNodeView`,
`TreeConnectorsView`, `BreadcrumbView`, plus `ThreeGenViewModelTests`; replace `TreeTabView`.

### Two discrepancies in the spec to resolve while implementing

1. **`BreadcrumbView` is described in its own section and used by `ThreeGenView`, but is
   missing from the "Files to create" list.** Create it — `Banyan/Views/Tree/BreadcrumbView.swift`.
2. **`TreeTabView` passes `ownerPersonId: focalId` into `ThreeGenView`**, but the "back to me"
   button disables when `focusedPersonId == ownerPersonId`. If the value passed is the *focal*
   id, that button is always disabled. The real owner id is `UUID(uuidString: ownerPersonIdString)`.
   Pass the actual owner id to `ThreeGenView`, and only use `focalId` for choosing the focal
   person. Confirm the "My tree" button enables/disables correctly.
